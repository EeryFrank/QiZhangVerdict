# 0.1.1 修复候选验收

验证日期：2026-09-25。该版本修复 Forge 1.20.1 的挑战／报告事件方向，并补充 Forge、NeoForge 的内置资源元数据；按项目要求采用 GPL-3.0-only，并在每个 JAR 内附 LICENSE / NOTICE。五个最终 GPL 成品的精确 SHA-256 与公开证据白名单在 `outputs/validation-0.1.1.json`；发行包另在根目录提供同一份 `validation.json`，证据根目录为 `outputs/`。

四端客户端不是开发类路径或模拟协议客户端。Forge 0.1.0 的实际失败记录和警告截图保留在 [客户端验收](client-matrix.md)，新版本在相同加载器上自动连接并完成报告。GPL 复测另有登录前超时的失败轮次，原样重试后通过；原日志保留，原因尚未确定，不以通过轮次抹去失败。[最终 Bukkit 验收](validation-0.1.1-gpl-bukkit.md) 区分现代分支夹具和旧版默认策略测试：现代夹具为覆盖分支缩短报告期限、提高合成账号数量上限，不能把它描述为完整默认策略测试。

新旧 JAR 的内容差异也已逐项核对：相对 0.1.0，行为代码变化在 Forge 网络事件处理类；其他变化是版本描述符、资源包元数据和许可文件。首次 0.1.1 内部候选完成测试后，按用户要求改为 GPL 并重建；所有 `.class` 与许可调整前逐字节相同，详见 `outputs/license-transition.json`。最终 GPL 包另外执行现代 Bukkit 和四端真实客户端验收，单独记录新散列；旧版 Paper 五站仍明确引用许可调整前候选的实测散列和代码等价证明，不改称为新散列重新运行。既有 0.1.0 标签、五个 JAR、安装 ZIP 和源码 ZIP 保留原字节；其 Forge 客户端后续发现的问题已写入两站原发布说明。

## 实测边界

测试没有运行作弊二进制、验证所有真实虚拟机型号或证明客户端报告无法伪造。设备摘要和模组列表来自客户端，重装系统、修改客户端、注入器或改名可能绕过这些信号。目录的 31 个 ID 是有源码证据的候选规则，原安装默认仍为 11 条，管理员通过显式合并或管理命令维护；不会自动恢复已删除的条目。

旧版插件 TCP 测试使用合成报告；没有对应版本真实客户端的旧版仍不能算作完整设备验证交付。1.18.2 / 1.19.4 模组使用独立 `0.2.0-dev` 版本推进，不属于这次五 JAR 发布。Folia、混合端、代理群服、基岩互通、长期大整合包、真实玩法误报率与压力测试仍未验收。此前 0.1.0 的单人、失败关闭及其他历史检查见 [原报告](validation.md)，未重新执行的项目不改称为 0.1.1 新实测。

Forge / NeoForge 安装组合含 AntiXray，没有 Grim 行为预测引擎。Fabric 的外部组件仍可能输出此前记录的非致命 refmap / 配方解析告警，运行通过不表示日志完全无告警；具体第三方问题继续见原报告与集成文档。

## 构建环境与远端 CI

本地使用 JDK 21 运行 Gradle，1.20.1 使用 Java 17 编译工具链。一次在线构建等待 Maven 元数据被主动终止；随后使用已经存在的完整依赖缓存离线构建成功，未关闭任何测试或 TLS 校验。最终日志和产物散列均单独记录。

GitHub Actions 和 GitLab CI 的配置均通过静态检查，GitLab API lint 返回 valid 且没有错误或警告。远端运行结果在发布说明中以实际 pipeline 状态为准；配置通过不等于 CI 已执行，GitLab 首版曾因共享运行额度不足而未执行任务。
