# Minecraft 1.17.1 专服与准入验证

最终 Fabric `bda006d2…` 与 Forge `a71d6bb2…` 两份 `0.6.0-dev` 成品分别在 Java 16 的同加载器专服通过 26 组 TCP 准入用例，共 52 次执行。两组最初均验证 13 项默认策略、44 条默认规则及生产环境命令 Mixin；测试结束恢复默认属性并确认 reload 生效，服务端正常退出 0、端口释放。完整散列见[构建记录](adapter-1.17.1.md)，各轮日志和结果见[专服报告](../outputs/runtime-server-1.17.1.json)。

| 最终实例 | 固定依赖 | 用时 | 结果 |
| --- | --- | ---: | --- |
| Fabric | Loader 0.19.5、API 0.46.1+1.17 | 113.223 秒 | 26 组通过，正常退出 0 |
| Forge | 37.1.1 | 111.284 秒 | 26 组通过，正常退出 0 |

用例包含同 IP 同设备与不同设备配额、名单增删、GLOB、黑白名单、IP、VM 自报信号、关联账号与设备封禁以及解封。它们使用合成报告和明确记录的临时账号、频率、超时等测试设置；不能视为 52 个真实作弊样本或全程默认配置。测试改动的规则不能拿来当新服模板。

命令隔离检查除了观察 required Mixin 应用日志，还导出实际目标类并用 javap 核对玩家命令到门禁的调用关系。最终两组没有观察到协议库 `PartialReadError`，这也不证明完整游戏协议或所有玩法兼容。

保留的 Forge 失败轮次有两种：第一轮官方安装器退出 0，但测试脚本错误地强制比较未被 processor outputs 引用的 PATCHED_SHA，因而在游戏启动前拒绝。脚本随后验证真正声明的输出散列，并强制独立重放全部 1252 个补丁输出类。第二轮旧产品包正常启动，但 FML-only 通道判断阻止向标准通道测试客户端发送挑战，首例报告超时。通道修复后的 d88 包在新实例通过 26 组，但后续图形准备发现其共享日志接口使用 NOP 后端。最终 a71 包改接现有 Log4j，再以全新实例重跑 26 组；实际日志确认 Verdict 启动和外部组件状态可见。其他依赖仍输出 SLF4J NOP 告警，原日志保留，未宣称整个 Forge 环境已无该告警。d88 的通过结果另列历史，旧失败未改写成成功。

这些都是本机回环、离线测试实例。没有证明正版身份认证、代理转发、其他加载器互通、生产负载、真实 VM 对抗或用户正式验收。旧版本已发布包和原始证据保持不变。
