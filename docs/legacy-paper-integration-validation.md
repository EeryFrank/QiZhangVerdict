## 实际检查内容

Verdict 完整 13 项严格默认策略前后 SHA256 始终为 `47310c31b47287ab805bfdbf8ddddf80e8169385bd9c862239a0a0075644da4e`。配套报告和设备字段均必需，期限 20 秒，VM 与黑名单策略为 DENY，拒绝后制裁为 BAN，同 IP 最多在线 3 人、同 IP 同设备最多 1 人。正常报告后连接保持至少 22 秒才开始注入违规。此处是合成报告，不能证明真实硬件或虚拟机身份。

完整 [Grim 旧版联动模板](../integrations/grim-legacy-2.3.67-verdict.example.yml) 的 SHA256 为 `a96bb3be1db525b17638e3a3a8c12f53e042b6dc0d75571e31edc808b0dfefd6`，每阶段启动、结束均逐字节一致。没有降低 `120:0` 阈值：每版发送 121 个相同快捷栏槽位数据包，间隔 160 毫秒；实际 Grim 控制台记录 BadPacketsA 的 x20、x40、x60、x80、x100、x120，随后执行 `qzverdict ban`。旧协议事务响应明确为 `accepted:true`，成功阶段未混入 BadPacketsS 告警。

第一个合成账号先报告同一设备并退出，第二个账号触发处罚；协议断言检查恰好两个账号和一个设备的持久封禁记录。重启后分别验证账号换设备仍被拒绝、历史关联账号仍被拒绝、新账号使用被封设备被拒绝、相同 IP 的独立设备允许，以及逐项解除账号和设备封禁后恢复准入。最终在私有状态文件中复核这组封禁记录已清空；**状态文件未公开**。本轮没有测试两个关联账号同时在线时的立即断线。

矿石场景固定在同一块区块、同一高度：隐藏钻石 `(8,32,8)`、邻接空气的可见钻石 `(12,32,8)`、石头对照 `(9,32,8)`。控制台独立确认前两个位置实际仍是钻石矿；收到的真实区块包解码分别为 **stone / diamond_ore / stone**。这证明这些明确坐标上的模式 1 隐藏与对照保留，不证明所有透视手段均被阻止，也没有执行挖掘后的揭露更新测试。

1.16.5 额外保留了两名合成账号收到的原始区块包。独立复核使用固定 `prismarine-chunk 1.41.0`、`minecraft-protocol 1.66.2` 和 Vec3 再次离线解码，核对数据长度、哈希及三个坐标；成功夹具的两份数据均吻合。[独立解码结果](../outputs/evidence/legacy-paper-integration-review-decoded-ore-review.json) / [复核脚本](../outputs/evidence/legacy-paper-integration-review-decode-ore.cjs)。1.8.8、1.12.2 保留运行时解码结果、完整日志和实际脚本快照，未留原始区块字节，因此不宣称对它们进行了同样的离线重解码。

## 保留的失败与告警

| 尝试 | 实际失败 | 后续修正及边界 |
| --- | --- | --- |
| 1.12.2 `01` | 旧 Paper 不接受 `--nogui`，启动前退出 0。 | 改用裸参数 `nogui`。该次没有启动成功，也没有正常世界保存，退出 0 不算通过。 |
| 1.12.2 `02` | 夹具回传事务的 `accepted=false`，实际累积 BadPacketsS；A 注入未到 120 即因组合计数被封，阈值断言失败。 | 改为 `accepted:true`。保留当次混合告警和失败断言，不能将其称为单项 A 达到 x120。 |
| 1.8.8 `01` | 区块读取器需要 Vec3，普通对象缺少 `modulus`，解码抛出 TypeError。 | 换用 Vec3 后重新运行独立夹具；旧结果保持失败。 |
| 1.16.5 `01` | 世界生成/场景准备未建立要求的石头体积，隐藏位置读到空气。 | 原始数据独立重解码为 air / air / air；后续先强制加载区块并显式填充 8448 块石头，再放置两个钻石和空气对照。 |

**1.16.5 最终成功夹具仍有** `No key layers/structures in MapLike[{}]` 和出生群系告警。通过结论依赖随后控制台确认建立的测试体积与真实方块、区块包证据；没有声称平坦世界生成参数本身已无误。Java 8 后续支持警告、旧插件 api-version/material 警告、终端警告、重复断线警告及已有文本编码异常也全部保留。这里只确认固定旧版本下的上述功能，不承诺上游仍提供支持或广泛游戏兼容。
